# 데모 시드 — 원본 파일이 붙은 문서

원본 파일(md·pdf)이 붙은 데모 문서 4건을 **실제 API 로** 등록하고, 그 문서를 인용하는 질문과
답변 평가를 남긴다. 검색·인용·원본 다운로드·PDF 하이라이트·피드백 드릴다운을 실제 데이터로
보여주기 위한 스크립트다.

| 문서 | 형식 | 범위(조직 / 팀) | 등록 계정 |
|---|---|---|---|
| 정보보안팀 접근권한 정기검토 회의록 | md | 보안본부 / 정보보안팀 | member |
| 사내 데이터 외부 반출 승인 정책 | md | 보안본부 | member |
| 인증팀 다단계 인증 도입 설계 문서 | md | 플랫폼본부 / 인증팀 | lead |
| 보안 로그 보관 기간 결정 기록 | pdf | 보안본부 / 정보보안팀 | member |

범위를 나눠 둔 것은 권한 필터를 보여주기 위해서다 — 같은 질문이라도 로그인한 계정의 조직·팀에
따라 볼 수 있는 문서와 인용되는 문서가 달라진다.

## 쓰는 법

스택이 떠 있어야 한다(`docker compose --profile app up -d --wait`). 표준 라이브러리만 쓴다.

```bash
cd deploy/demo-seed
python3 seed_demo_data.py --dry-run   # 무엇을 등록할지만 본다
python3 seed_demo_data.py             # 등록 + 질문·평가
python3 seed_demo_data.py --no-chat   # 문서만 등록(모델 호출 없음)
python3 seed_demo_data.py --check     # 현재 상태만 본다
```

**다시 돌려도 안전하다.** 제목이 같은 문서가 있으면 건너뛰고, 파일이 붙은 인용과 평가가 이미
있으면 질문 단계도 건너뛴다. 질문 단계는 모델을 호출하므로 몇 분 걸린다(LLM 키가 없으면 근거
발췌 모드로 답한다).

## 왜 SQL 시드가 아닌가

`auth-service` 의 `db/seed` 는 조직·사용자·정책만 심는다. 문서는 SQL 로 심을 수 없다.

- 원본 파일의 **바이트가 MinIO 에 들어가야** 한다. `document_file` 행만 넣으면 "원본 받기"가
  저장소에 없는 키를 가리켜 서명 URL 이 404 를 준다.
- 색인이 돌아야 청크·벡터가 생긴다. 청크가 없으면 검색·인용 대상이 되지 않는다.

## 왜 일괄 가져오기(import) 경로인가

`POST /api/documents` 로 만들고 `POST /api/documents/{id}/file` 로 파일을 붙이면, 생성 이벤트가
파일보다 먼저 처리돼 한 번은 본문(`content.md`)으로 색인된다. 파일 업로드가 재색인을 다시 걸어
결국 맞춰지지만 색인이 두 번 돈다.

`POST /api/document-imports` 는 문서·파일·아웃박스 이벤트를 **한 트랜잭션**에서 만든다
(`ImportItemService.attemptImport`). 색인기가 그 문서를 읽을 때는 `document_file` 이 이미 있어서
처음부터 원본 파일에서 파싱한다.

가져오기는 `decision_status` 를 `UNDECIDED` 로 두고 `project_name` 을 비운다. 화면에서 수정해
채워도 원본 파일과 좌표는 유지된다 — 원본은 "현재 판 이하에서 가장 최근에 올라온 것"을 쓴다.

## md 와 pdf 를 섞은 이유

같은 "원본 파일이 붙은 문서"인데 얻는 것이 다르다.

| 원본 | 절 구조(`section_path`) | 좌표(`bboxes`) |
|---|---|---|
| `.md` | 헤딩이 절 경로가 된다 | 없다 |
| `.pdf` | **글자 크기로 추정한** 헤딩이 절 경로가 된다 | **있다** — 인용된 절만 원본 위에 하이라이트한다 |

PDF 헤딩은 추정이라 보장이 아니다. 크기 변화가 없는 균일 서식 PDF 는 헤딩 없이 한 덩어리가 된다.

마크다운 문서는 `front/src/lib/documentTemplates.ts` 의 문서 템플릿 절 이름을 그대로 따른다.
템플릿이 실제로 어떤 `section_path`·`chunk_tag` 를 만드는지 데모에서 보여준다.

`server/python/index-worker/tests/test_demo_seed_documents.py` 가 이 문서들을 실제 파서로
검증한다. 문구를 손보다 절 구조나 DECISION 절을 깨면 그 테스트가 잡는다 — 화면에는 아무 오류도
뜨지 않고 검색·타임라인만 조용히 나빠지는 종류의 회귀다.

## PDF 를 다시 만들려면

`make_pdf.py` 가 만든다. reportlab 이 필요해서 시드 본체와 분리했다 — 시드는 표준
라이브러리만으로 돌아야 한다.

```bash
python3 -m venv venv && ./venv/bin/pip install reportlab
./venv/bin/python make_pdf.py
```

PDF 메타데이터(제목·작성자·생성일)를 채우는 것이 중요하다. 가져오기의
`DocumentMetadataExtractor` 가 그 값을 문서 제목·작성자·**작성일**로 쓴다. 비워 두면 작성일이
가져온 날짜가 되어 타임라인이 오늘로 몰린다. 한글 폰트를 심지 않으면 글자가 깨져 pdfplumber 가
뽑는 텍스트까지 깨진다 — 색인이 조용히 망가진다.

## 한계

- **평가는 4건(유용 3 / 아니오 1)만 남긴다.** 지표 3 의 판정 기준(20건)에 못 미쳐 화면에 "표본
  부족"으로 뜨는 것이 맞는 동작이다. 20건을 채우려면 평가를 지어내야 하고, 그러면 지표가 거짓이
  된다. 드릴다운 화면이 동작하는 것을 보여주는 데 필요한 최소만 심는다.
- **PDF 가 1건이다.** 하이라이트 경로와 헤딩 추정을 보여주는 데는 충분하지만, 서식이 다양한
  실제 PDF 에서의 헤딩 추정 정확도를 평가할 표본은 아니다.
- 시드는 문서를 지우지 않는다. 되돌리려면 관리자 화면에서 해당 문서를 삭제한다.
