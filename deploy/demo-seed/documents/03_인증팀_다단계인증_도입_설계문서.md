# 인증팀 다단계 인증(MFA) 도입 설계

사내 관리자 화면에 다단계 인증을 넣는 설계다. 2025 Q3 세션 타임아웃 단축 정책의 후속이다.

## 배경과 목표

세션 타임아웃을 30분으로 줄인 뒤 계정 탈취 시도 자체는 줄지 않았고 재로그인 불만만 늘었다.
타임아웃 단축은 탈취 이후 창을 좁히는 조치이고, 탈취 자체를 막는 수단이 아니다.
목표는 관리자 권한 계정의 로그인에 두 번째 인증 요소를 요구하는 것이다.
성공 기준은 관리자 계정 100%가 MFA를 등록하고, 로그인 실패율이 도입 전보다 2%p 이상 늘지 않는 것이다.

## 제안하는 설계

TOTP(시간 기반 일회용 비밀번호)를 1차 수단으로 쓴다. 로그인 성공 직후 TOTP 검증 단계를 두고,
검증 전에는 액세스 토큰을 발급하지 않는다. 등록 시 복구 코드 10개를 한 번만 보여주고 해시로 보관한다.
신뢰 기기 기억은 30일로 두고, 기기 목록과 강제 로그아웃을 사용자 화면에서 제공한다.

## 검토한 대안

- SMS 인증 — 사용자가 추가 앱을 설치하지 않아도 되지만, SIM 스와핑에 취약하고 발송 비용이 계정 수에 비례해 늘어난다. 고르지 않았다.
- 하드웨어 보안키(WebAuthn) — 보안 수준이 가장 높지만 전 관리자에게 키를 배포하는 비용과 분실 대응 절차가 부담이다. 2차 단계로 미뤘다.
- 이메일 일회용 링크 — 메일 계정이 함께 탈취되면 의미가 없어 두 번째 요소로 보기 어렵다. 고르지 않았다.

## 결정 사항

- 1단계는 TOTP로 확정한다. WebAuthn은 2027 상반기에 다시 본다.
- 적용 대상은 SYSTEM_ADMIN과 TEAM_ADMIN 역할 보유 계정으로 한정한다.
- 복구 코드는 재발급 시 기존 코드를 모두 폐기한다.

## 위험과 대응

기기를 분실하면 로그인이 막힌다. 복구 코드와 관리자 초기화 절차를 함께 준다.
서버 시각이 틀어지면 TOTP가 전부 실패한다. 시각 동기 확인을 배포 점검 항목에 넣는다.
도입 직후 문의가 몰릴 수 있어 관리자 대상 안내를 2주 전에 먼저 보낸다.

## 영향 범위

auth-service 로그인 흐름과 게이트웨이 토큰 발급 경로가 바뀐다.
관리자 화면 로그인 UI와 사용자 계정 설정 화면에 등록·해제 단계가 늘어난다.
2025 Q3 세션 타임아웃 단축 정책은 유지한다 — 이 설계가 그 정책을 대체하지 않는다.
